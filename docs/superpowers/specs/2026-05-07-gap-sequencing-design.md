## 核心决策(brainstorm 已逐项拍)

### 1. 三个前置问题已拍

| # | 问题 | 决策 |
|---|---|---|
| Q1 | 决策层是否会真用导出? | **不会** — 决策层非系统用户(PRD §1.1 印证),G4 仅做 I1 截图,I2 PDF / I3 脱敏不做 |
| Q2 | 审计在生产态是否必须? | **不做** — 没有合规硬要求,无主动排查痛点 |
| Q3 | 离职在生产期间会真实发生吗? | **运营兜底** — 真触发走手工 SQL,不做产品化 |

→ **G5 H 审计** 和 **G7 数据归属转移** 从 G1-G8 列表划掉。

### 2. G1 工具池的真实定位:反推角色落位

中台 GA 这个角色在 POP 项目的实际状态是 **D — 角色虚位,内容产出方不存在**。但 G1 仍要做,**目的不是服务现有用户,是用具象化的系统反推岗位编制**。

- **反推产物主线:** 给 GA 负责人 / 公司高层看 — "我需要为 POP 配一个中台 GA,系统已经在那儿等他了"
- **副产物:** 用户自己边跑边调,验证 PRD §1.4 + §2.3 的中台 GA 工作流定义是否准确
- **不做:** 给假想候选人达到生产形态深度(B 选项被否)

→ **G1 范围从 D1-D13 全集 ~25% 砍到最小 demo 闭环 ~5-7 天:** 中台 GA 上传(成品文档 + 调用接口配置两类)→ 渲染到点详情 → 属地 GA 下载/调用 → 消费记录。D14/D15 P1 不做。

### 3. G1 内容 seed 方案

中台 GA 不存在 → 内容产出方空缺。决策:

- **AI 生成 + 用户 review 修订 + seed 进 db**
- **数量目标:5 主题(V2G / 虚拟电厂 / 充电基础设施 / 新型储能 / 电力市场)各 1-2 个工具,共 6-10 个**
- **类型分布:** 成品文档 + 调用接口两类都覆盖
- 过 PRD §0.5 的 ≥ 3 工具门槛,对负责人 demo 时不空载
- 跟 policies seed 同模式(LLM 离线产出 + 手动喂给后端)

### 4. G1 / G6 排序:G6 先,G1 后(不并行)

候选 A 默认是 G1 → G6,但那是演示态思路。在生产态 + 真用户已在用 + 反推 demo 这个组合下:

- G6 ~3-5 天,prod 上属地 GA 已是真用户,F1/F2/F4 是每日入口,小工作量大可见度
- G1 demo 集要先做反推 demo 形态设计(上传 / 渲染 / 消费记录),G6 可当 warmup
- 串行省 context switch
- **顺序原则:先稳真用户,再做反推 demo**

### 5. G1 反推执行期 review point(不写进任务)

做完 G1 demo 集给负责人讲完后,主动决策——是继续投入到 D14/D15 全集深度,还是砍住认账"反推未成"。**不能默认靠惯性继续做**。这条放执行期口头 check,不做成 spec/plan 任务项。

## 5. 已知问题 / Tech Debt

### 5.1 性能 — prod 网页慢(未优化)

- **主 JS bundle:** 2.6MB(gzipped 838KB),首屏下载 16 秒
- **后端:** 本机 /health 5-17ms,完全没问题
- **根因:** Caddy 没开 gzip + Vite 没 code splitting + 没 CDN
- **优化级别(未做):**
  - Level 1 · Caddy `encode gzip zstd`(5 分钟,16s → 5s)— **强烈推荐先做这个**
  - Level 2 · 浏览器缓存头(5 分钟,二次访问 0s)
  - Level 3 · 前端 code splitting echarts + antd lazy load(1-2 天)
  - Level 4 · OSS + CDN 托管 dist/(半天-1 天,最优解)

### 5.2 ssh 22 易被云盾误封

- 阿里云**云盾防爆破**有自己的活跃黑名单,跟控制台白名单是两份独立数据
- 失败几次就静默封 IP,sshd 不发 banner,iptables 看不到
- **当前 workaround:** 从代理出口 IP 走 Clash DIRECT 规则(已配 `47.238.72.38/32` + `xiaojuenergy.com`)
- **长期方案没做:** sshd 改 2222 端口 + ECS 安全组开 2222,**避免每次出问题就走 Workbench**

### 5.3 OSS bucket 权限过宽

- 给的是 `AliyunOSSFullAccess` 系统策略 = AK 能访问账号下**所有 bucket**
- 真用 demo 没问题,**生产严格化时收紧为 bucket-scoped 自定义策略**

### 5.4 数据更新链路没固化

- policies 是 LLM 离线生成 JSON 导入,**没有定期更新机制**
- tools 是手 seed,**中台 GA 真上传文档的流程还没人跑过**(反推 demo 后再说)

### 5.5 geojson 错误

- 启动日志有 `加载 710000.json 失败 SyntaxError`(台湾省 GeoJSON 是 XML 不是 JSON)
- 不影响功能,但日志噪音


```bash
env -u HTTPS_PROXY -u https_proxy curl --noproxy '*' -s https://xiaojuenergy.com/api/v1/health
```

### prod psql 查表
```bash
ssh -i ~/Desktop/pop-server-key.pem root@47.238.72.38 \
  "sudo -u postgres psql pop -c \"SELECT COUNT(*) FROM tools;\""
```

### Deploy 7 步(已有 main 上新 commit 时)
```bash

npm run build --workspace=@pop/web
cd apps/api && npm run migration:run
pm2 restart pop-api --update-env
curl -s http://localhost:3001/api/v1/health
EOF
```

### 5.5 geojson 错误 ✅ DONE (2026-05-18)

### 5.6 ⚠️ 新增 — CPU 100% 完全卡死事件(2026-05-18 ~13:00)

**症状**:
- pop-api 部署成功后 ~1 小时,服务器 CPU 飙到 100%
- ECS 完全无响应:SSH 22 / HTTP 80 / HTTPS 443 三端口 TCP 都能 CONNECT(内核网络栈活着),但**应用层全挂**(sshd/Caddy/pop-api 都不回字节)
- 阿里云 Workbench 也 SocketTimeoutException 进不去
- ping 通,traceroute 通 — IP 层路由正常
- ECS 监控:CPU 100%,内存/磁盘读不到(监控代理也卡了)

**诊断**(重启后查):
- ✗ 不是 OOM(`journalctl -k` 没记录 killed process)
- ✗ 不是 pop-api 自身死循环(错误日志干净,没异常 stack)
- ✗ 不是内存问题(重启后 mem 1.6G 总,532M used,swap 0)
- ⚠️ **没拿到铁证根因** — 死机时进程没机会写日志,事后日志缺失

**最大嫌疑**:
- 阿里云宿主层 noisy 邻居(共享物理机,小规格 ECS 易碰)
- 某个非 pop-api 系统进程死循环(pm2 list 没有其他业务进程)

**恢复**:
- 阿里云控制台 → 强制重启 → 5 分钟回来 → systemd + pm2 自启 sshd/Caddy/pop-api → 全部恢复

**预防建议**(没做,等下次 session 拍):
1. `pm2 restart pop-api --max-memory-restart 1G` — 防御性,万一 pop-api 哪天泄漏自动重启不连累全机
2. 阿里云控制台开 CPU > 80% 持续 5 分钟告警 — 提前介入
3. `apt install atop` + 持续采样 — 下次出问题事后能回溯
